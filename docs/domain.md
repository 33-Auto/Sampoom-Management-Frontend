# 업무 흐름과 용어

[README](../README.md)로 돌아가기

화면을 고치기 전에 그 화면이 업무의 어느 단계인지 알면 도움이 됩니다. 이 문서는 원래 백엔드가 설계한 흐름을 기준으로 씁니다. 목 서버에서는 모듈마다 데이터가 따로라서, 한 화면에서 처리한 결과가 다음 단계 화면으로 넘어가지 않습니다.

## 이름

- **삼품관리(Sampoom Management)**: 이 ERP의 제품 이름입니다. 로그인 화면 로고에는 "三품 관리"로 쓰여 있습니다.
- **삼삼오토**: 화면 속 회사 이름입니다. 팀 조직 이름 33-Auto를 한글로 읽은 것입니다.
- **33-Auto**: 팀의 GitHub 조직입니다. 이 저장소와 백엔드, 모바일 앱 저장소가 모두 여기 있습니다.

## 부품이 움직이는 순서

1. **대리점이 부품을 주문합니다.** 대리점은 이 회사에서 부품을 받아 차량을 수리하는 곳입니다. 대리점 직원은 앱에서 수리용 부품의 재고를 보고, 모자라면 부품을 주문합니다. 앱은 이 저장소가 아니라 같은 조직의 Android, iOS 저장소에 있고, 백엔드가 없어 지금은 동작하지 않습니다. 웹에는 대리점 전용 화면이 없어서, 대리점 계정으로 들어가도 다른 계정과 같은 홈이 보입니다.
2. **판매 관리가 주문을 받습니다.** 들어온 주문은 판매 주문에 창고별로 쌓입니다. 어느 창고로 보낼지는 백엔드가 가장 알맞은 창고를 고른다고 가정하고 만들었습니다. 판매 관리 화면에서는 주문을 취소할 수 있습니다.
3. **재고 관리(WMS)가 출고합니다.** 같은 주문이 출고 지시에 창고 재고와 함께 보입니다. 출고를 처리하면 그만큼 창고 재고가 줄어듭니다.
4. **창고가 공장에 발주합니다.** 창고 재고가 ROP 아래로 내려가면 창고가 공장에 부품을 주문합니다. ROP 설정에서 자동 발주를 켠 부품은 이 주문이 자동으로 나가도록 설계했습니다. 발주와 그 입고는 재고 관리의 발주 관리에서 다룹니다. 여기서 발주는 외부 업체가 아니라 공장에 내는 부품 주문입니다.
5. **생산 관리가 부품을 만듭니다.** 창고의 발주는 생산 관리에 부품 주문으로 들어옵니다. 공장은 생산 스케줄(MPS)로 무엇을 언제 얼마나 만들지 정하고, 생산 계획(MRP)에서 BOM으로 필요한 자재를 계산해 적용한 뒤, 생산 지시(MES)에서 진행 상황을 관리합니다. 탭은 MES, MRP, MPS 순서라 이 업무 순서와 반대인데, 일부러 이렇게 두었습니다.
6. **구매 관리가 원자재를 사 옵니다.** MRP 결과를 적용할 때 자재가 모자라면 구매 요청이 함께 만들어져 구매 관리로 넘어갑니다. 구매 관리는 공장이 생산에 쓰는 원자재처럼 이 회사가 만들지 않는 기초 자재를 외부에서 사 오는 일을 맡습니다. 원자재 공급처도 원래 구매 관리에서 관리할 몫이었지만, 공장이 구매를 자동으로 요청한다는 전제로 만들어서 공급처를 다루는 화면은 없습니다.

바탕 데이터는 **기준 정보 관리**에서, 직원 정보는 **인사 관리(HRM)**에서 다룹니다.

## 모듈별로 알아 둘 점

- **기준 정보:** 품목은 부품과 원자재를 함께 다룹니다. 지점은 창고와 공장 같은 사업장으로, 판매 관리와 재고 관리의 위쪽 선택칸에서는 창고를, 생산 관리에서는 공장을 고를 때 쓰입니다. 거래처는 부품을 받아 가는 대리점이고, 판매 주문의 고객사 필터에 쓰입니다. 작업장과 공정은 생산 관리용 데이터이고, 공정의 단계마다 작업장이 하나씩 붙습니다.
- **생산 지시(MES):** "부품 주문 목록"은 창고가 공장에 요청한 부품 생산 주문입니다. 주문 코드의 `WO-`는 작업 지시(Work Order)의 줄임말입니다. 요청일은 창고가 부품이 필요하다고 한 날짜(`requiredDate`), 계획일은 공장의 생산 예정일(`scheduledDate`)입니다.
- **구매 관리:** 화면은 원자재 구매 요청 하나입니다. 이름이 비슷한 발주 관리는 창고가 공장에 내는 부품 주문이라 재고 관리에 있습니다.
- **인사 관리:** 직원 목록에서 직원 정보를 고치고 재직 상태(`ACTIVE`, `LEAVE`, `RETIRED`)를 바꿀 수 있습니다.

## 문서와 상태 값

상태 이름은 API 규격(`public/openapi.json`)의 값을 그대로 씁니다. 상태를 바꾸는 업무 규칙은 백엔드에 있었고, 목 서버는 출고 처리, 입고 처리, 주문 취소처럼 일부 동작에서만 상태를 바꿉니다.

| 문서                 | 모듈                 | 상태 값                                                                                                                                                       |
| -------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 판매 주문, 출고 지시 | 판매 관리, 재고 관리 | `PENDING` 대기, `CONFIRMED` 확인, `SHIPPING`, `SHIPPED`, `DELIVERING`, `ARRIVED` 출고와 배송 단계, `COMPLETED` 완료, `DELAYED` 지연, `CANCELED` 취소          |
| 발주, 부품 주문      | 재고 관리, 생산 관리 | `UNDER_REVIEW` 검토중, `PLAN_CONFIRMED` 계획 확정, `IN_PROGRESS` 진행중, `COMPLETED` 완료, `DELAYED` 지연, `PURCHASE_REQUEST` 자재 구매 요청, `REJECTED` 반려 |
| 생산 스케줄(MPS)     | 생산 관리            | `PLANNED` 계획, `PROCESSING` 진행중, `COMPLETED` 완료, `CANCELLED` 취소                                                                                       |
| 구매 요청            | 구매 관리            | `ORDERED` 주문됨, `RECEIVED` 수령됨, `CANCELED` 취소됨                                                                                                        |

- 판매 주문과 출고 지시는 같은 주문이라 상태 값도 같습니다. 목 서버에서는 판매 관리에서 취소하면 `CANCELED`가 되고, 재고 관리에서 출고하면 남은 수량이 있을 때 `SHIPPING`, 다 나가면 `SHIPPED`가 됩니다.
- 발주와 부품 주문은 창고가 낸 주문을 공장이 받은 것이라 상태 값도 같습니다. 코드는 원래 백엔드에서도 달랐습니다. 공장이 창고의 발주(`PO-`)를 받으면 자기 코드(`WO-`)를 새로 붙이고, 발주 ID(`externalPartOrderId`)로 둘을 연결했습니다. 목 데이터에서는 두 모듈의 주문이 서로 연결돼 있지 않습니다.
- MPS의 취소만 `CANCELLED`로 철자가 다릅니다. 규격 값이므로 그대로 씁니다.

## 용어

| 용어                                 | 뜻                                                                           |
| ------------------------------------ | ---------------------------------------------------------------------------- |
| BOM (Bill of Materials)              | 부품 하나를 만드는 데 들어가는 자재와 수량 목록                              |
| MPS (Master Production Schedule)     | 무엇을 언제 얼마나 만들지 정한 기준 생산 일정                                |
| MRP (Material Requirements Planning) | MPS와 BOM으로 필요한 자재의 양과 시점을 계산하는 생산 계획                   |
| MES (Manufacturing Execution System) | 현장에 생산을 지시하고 진행 상황을 관리하는 단계                             |
| WMS (Warehouse Management System)    | 창고의 재고와 입출고를 관리하는 시스템                                       |
| ROP (Reorder Point)                  | 재고가 이 수량 아래로 내려가면 다시 주문하는 기준점                          |
| PO (Purchase Order)                  | 발주서. 재고 관리의 발주 관리 화면에서 창고가 공장에 낸 부품 주문을 다룹니다 |
